# ملصقات المنتجات

مُنشئ عام لملصقات باركود و QR للمنتجات بمختلف أنواعها، يعمل في المتصفح ويطبع على طابعات الملصقات الحرارية (مثل Xprinter) بأي مقاس.

الرابط الحالي: https://luay89.github.io/pharmacy-labels/

> استضافة GitHub Pages الحالية لا تشغّل خادم الشراء. يلزم نشر نسخة Node.js على HTTPS وربط نطاق الموقع بها قبل تفعيل التجربة المحدودة أو Stripe.

- Code 128 و EAN-13 و QR
- ترقيم تلقائي مشتق من اسم المنتج مع رقم تسلسلي فريد في Code 128 وQR؛ أما EAN-13 فيبقى رقمياً حسب المعيار
- الاسم والسعر وتاريخ الانتهاء ورقم الدفعة حقول اختيارية تناسب أنواع المنتجات المختلفة
- وضع نهاري/ليلي اختياري (نهاري، ليلي، أو حسب إعداد الجهاز)
- اختيار لغة الواجهة من أشهر اللغات (العربية، الإنجليزية، الصينية، الهندية، الإسبانية، الفرنسية، البرتغالية، الأردية، الروسية، اليابانية، الألمانية)
- مقاسات جاهزة ومقاس مخصص
- حفظ المنتجات في المتصفح، وتصدير واستيراد Excel
- أول 20 ملصق مجانًا، ثم فتح لمرة واحدة بسعر 5$ (بعد نشر الخادم وإعداد Stripe)
- ملفات الباركود وExcel مضمّنة محليًا؛ يتطلب حجز الطباعة والشراء اتصالًا بخادم التطبيق

## تطبيق Android

يوجد تطبيق Android مستقل في مجلد `android/`. يضمّن صفحة الويب محليًا وتُحفظ المنتجات على الجهاز، لكن قفل الطباعة الآمن يعتمد الآن على API الويب؛ لذلك لن يعمل الطباعة/الحفظ التجاري من التطبيق المحلي حتى إضافة جسر Android يتصل بالخادم وربط Google Play Billing. لا تنشر نسخة Android الحالية للبيع بعد.

يتطلب البناء JDK 17 وأدوات Android SDK. لبناء APK تصحيح قابل للتثبيت:

```sh
cd android
JAVA_HOME=/path/to/jdk-17 ./gradlew assembleDebug
```

سيظهر الملف في `android/app/build/outputs/apk/debug/app-debug.apk`. تتم مزامنة `index.html` تلقائياً إلى أصول Android قبل البناء.

## الأمان

- تم تحديث مكتبة Excel المضمنة إلى **SheetJS CE 0.20.3** لمعالجة CVE-2023-30533 (Prototype Pollution عند قراءة ملفات خبيثة).
- لا تُخزّن حالة الشراء أو عدّاد التجربة في `localStorage`؛ يحفظهما الخادم في SQLite ويرتبطان بملف تعريف ارتباط `HttpOnly` موقّع.
- يتحقق الخادم من جلسة Stripe مباشرة، ويتحقق من توقيع Webhook، ويحدّ من محاولات إنشاء الدفع وحجز الملصقات.

## تشغيل خادم الويب

يتطلب Node.js 22.9 أو أحدث:

```sh
npm ci
cp .env.example .env
# أنشئ قيمة عشوائية: openssl rand -hex 32
# ضعها في SESSION_SECRET داخل .env
npm start
```

يفتح التطبيق محليًا على `http://localhost:3000`. قاعدة بيانات SQLite تُنشأ داخل `data/`، لذا يجب إعداد تخزين دائم عند الاستضافة وعدم تشغيل عدة نسخ مستقلة على قواعد بيانات محلية مختلفة.

## ربط Stripe Checkout

أضف هذه القيم إلى `.env` أو إلى إعدادات الأسرار في منصة الاستضافة:

- `STRIPE_SECRET_KEY`: مفتاح Stripe السري (استخدم مفتاح الاختبار أولًا)
- `STRIPE_WEBHOOK_SECRET`: سر Webhook بعد إنشاء نقطة `/api/stripe/webhook`
- `PUBLIC_APP_URL`: عنوان الموقع العام على HTTPS
- `SESSION_SECRET`: قيمة عشوائية مستقلة، لا تُرسل للمتصفح ولا تُضمّن في Git

الخادم ينشئ Checkout لمرة واحدة بمبلغ ثابت **500 سنت USD (5.00$)**. بعد الدفع يتحقق من Stripe API، ويقبل كذلك Webhook الموقّع `checkout.session.completed`. لا يقبل الخادم رمز شراء يرسله المستخدم يدويًا ولا يعتمد على حالة محفوظة من جهة العميل.

عند إنشاء نقطة Webhook في لوحة Stripe اختر هذه الأحداث فقط:
`checkout.session.completed`، `checkout.session.async_payment_succeeded`، `checkout.session.async_payment_failed`، `charge.refunded`، `charge.dispute.created`، `charge.dispute.closed`.

لا يُفتح التطبيق إلا عندما تكون الجلسة `paid` بمبلغ 500 سنت USD ومرتبطة بنفس جلسة المستخدم؛ الدفع المعلّق أو الفاشل أو الملغى لا يمنح أي صلاحية، والأحداث المكررة تُعالج مرة واحدة.

في وضع الاختبار، مرّر Webhook إلى جهازك باستخدام Stripe CLI:

```sh
stripe listen --forward-to localhost:3000/api/stripe/webhook
```

انسخ قيمة `whsec_...` التي يعرضها Stripe CLI إلى `STRIPE_WEBHOOK_SECRET`، ثم اختبر الدفع بمفاتيح Stripe الاختبارية. لا تستخدم مفاتيح Live حتى ينجح اختبار الدفع والعودة وتأكيد Webhook على HTTPS مع تخزين دائم. لا توجد مفاتيح Stripe في المستودع.

## جاهزية النشر على المنصات

- ✅ **Web/PWA**: تمت إضافة `manifest.webmanifest` و`sw.js`؛ يتطلب التثبيت مع الشراء نشر خادم Node على HTTPS.
- ⏳ **Stripe Web**: مسارات Checkout والتحقق والخطاف موجودة، لكنها تحتاج حساب Stripe ومفاتيح واختبارًا على استضافة HTTPS.
- ⏳ **Android / Google Play**: مشروع Android موجود، لكن يلزم Android SDK وتوقيع إصدار وربط جسر API وGoogle Play Billing؛ لا يستخدم مسار Stripe الويب تلقائيًا.
- ⏳ **Apple App Store**: يحتاج حزمة iOS أصلية (مثل Capacitor/Cordova أو مشروع iOS مستقل) + تكامل StoreKit.
- ⏳ **Huawei AppGallery**: يحتاج تكامل IAP الخاص بهواوي داخل عميل Android خاص بـ AppGallery.

هذه المنصات تحتاج حسابات مطور، شهادات توقيع، ومفاتيح نشر لا يمكن تجهيزها دون بياناتك الرسمية. حدّ التجربة مربوط بجلسة متصفح مجهولة على الخادم، وليس بهوية شخص؛ يمكن بدء تجربة جديدة بمسح ملفات المتصفح. يلزم إضافة تسجيل دخول موثّق وربط الشراء بالبريد/الحساب قبل اعتبار حدّ التجربة أو استعادة الشراء مانعًا قويًا للتحايل.
